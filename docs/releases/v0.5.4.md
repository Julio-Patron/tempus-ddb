Security hardening of the 0.5 line. Every change turns a previously accepted input into a refusal or a signed denial, with one documented exception noted under pattern matching. First PyPI and crates.io release with default-deny on `tempus init` and independent verification.

### Security
- **Exact numbers and duplicate keys.** Signed documents accept only exact numbers (no floats, no integers beyond `i64`/`u64`; `NaN`, `Infinity`, `1e400` and `-0` are `NON_EXACT_NUMBER`). Repeated JSON object keys are refused with `DUPLICATE_JSON_KEY` by the gate, the Rust executor and the Python runtime.
- **Money parity between gate and payment executor.** `allowed_currencies` takes exact 3-letter codes only; payment actions require a `money` object with a non-zero amount; `"5."` and non-ASCII digits are refused on both sides; the beneficiary must be a non-empty string and is never stringified.
- **Pattern matching by component.** A `*` matches only as a whole component between `.` or `/`, in policy lists, the HTTP domain allowlist and the payment beneficiary allowlist. A `*` glued to text (`host*`) now matches nothing. A `*` that is its own leading or middle component (`*.example.com`) used to be a dead literal and now matches: review such entries before upgrading.
- **Ambiguous transport outcomes are `UNKNOWN`.** Timeouts, resets, TLS and HTTP 5xx are classified by exception type, recorded as `UNKNOWN` and never retried. Validation and other definitive errors stay `FAILED`.
- **HTTP executor fails closed.** Refuses to start with an auth header and no allowlist, blocks loopback, private and metadata destinations by resolved address and pins the connection, refuses `.` and `..` path segments. HTTP, GitHub and Slack executors refuse redirects.
- **Independent verification.** `verify-receipt`, `verify-trace --strict`, `export-bundle` and `verify-bundle` check evidence against a pinned gate public key with no database, reject unknown fields and duplicate keys, and expose `--require-execution`, `--require-checkpoint` and `--require-decision`.
- **Default-deny.** `tempus init` installs no policy; the gate signs a denial for every action until `install-policy` runs. The development allow-all policy is explicit (`--allow-all-dev`).

### Upgrading from 0.5.3
- Follow the README section "Common cases that now break, and how to fix them".
- A stored dev allow-all policy whose currency list is not exact codes fails with `TEMPUS_POLICY_INVALID`; replace it with `tempus install-policy --allow-all-dev`.
- Evidence produced under the 0.5.3 dev allow-all policy verifies as `INVALID`, and a permit issued before the upgrade under that policy cannot be committed. Finish or discard in-flight dev permits before upgrading. Policies with exact currency codes are not affected.

### Release process
- `v*` tag push builds wheels and sdist, attests provenance plus SPDX and CycloneDX SBOMs, waits for approval on the `release` environment and publishes through Trusted Publishing (OIDC) to PyPI and crates.io. Verify downloads with the commands in [docs/RELEASING.md](https://github.com/Julio-Patron/tempus-ddb/blob/main/docs/RELEASING.md).

Install: `python -m pip install tempus-ddb==0.5.4`
